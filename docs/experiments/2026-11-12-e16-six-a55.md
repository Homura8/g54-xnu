# E16: six Cortex-A55 cores

Hypothesis: the existing pinned K2 PSCI/SMP path can start the G54's six
A55s, reducing single-CPU contention during iOS boot.

## Inputs and checks

- Firmware 5-8-6, slot A, unlocked, bootloader Fastboot;
  `snapshot-update-status=none`, rechecked live before the flash.
- K2 kernel unchanged from E15 (CI 43265320296), SHA-256
  `2bb9311a91e2c59552e961c2dcee4a916ee65a47bff024de6fcb9bdc543f43dc`.
- Probe and ADT byte-identical to E15. The complete uncompressed SWEETXNU
  payload compares equal to E15 after replacing only `cpus=1` with `cpus=6`.
- Experimental boot SHA-256:
  `694380991abe01e1943146f7c81b9ab115c12cdc4251e38f6985fdd83d8a88d2`.
- Stock restore boot SHA-256:
  `e0fe4010a8a897e0b99253d4a51665582a850d6bb10837f535ebe3e0337cc2d4`.
- Root is the writable E15 iOS root, with its first-boot state retained.
  This is also a warm boot, so elapsed-time differences cannot be attributed
  solely to CPU count.

Pinned topaz patches 0065/0078 implement PSCI CPU_ON through SMC and verify
each selected CPU with SGI1. The G54 ADT already supplies the observed
MPIDR affinities `0x000`–`0x500`. A78 cores are not described or tested.

## Result

`fastboot flash boot_a out/g4/e16-smp-boot.img` completed OKAY in 1.987 s.
Reboot issued at **18:11:16 UTC, 12 November 2026**.

The owner explicitly reported **"6/6 CPUs verified, its still progressing
through boot"**, in response to checking
`6/6 CPUs initialized, SGI1 verified`.
Six-A55 startup is therefore owner-observed. No new GUI result or measured
speed-up is established yet. Wait for the current boot's process samples
before choosing the next GUI change; do not restart it before observation.

Rollback: flash E15's single-core image or the matching stock boot image
to `boot_a`. Android additionally requires userdata reset. No userdata,
slot-switch, bootloader or critical-partition write was performed by E16.
