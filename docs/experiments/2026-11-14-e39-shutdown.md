## Observations (owner)

| Run | Condition | Observation |
| --- | --- | --- |
| E39a | USB charger connected | Powered off in **under 30 s**, then **immediately started again** (booted `boot_a`). The probe's previous-boot page showed `NO VALID RING`: RAM was not retained, i.e. a real power cycle, not a warm reset (E38's panic reset kept the log) |
| E39b | **Battery only** | Powered off in about **15 s** and **stayed off** |
| E39c | Restart from iOS | **Restarted back into iOS** (not Fastboot), so 0207's SYSTEM_RESET path and the reboot-mode nibble clearing work. Previous-boot page: `NO VALID RING` (RAM not retained across this reset, unlike the 0201 panic reset in E38) |

## Interpretation

- PSCI SYSTEM_OFF works on the MT6855 BL31 once the `smc` is really
  executed; E38's failure was entirely the assembler `;` comment.
- With external power present, the PMIC/bootloader powers the phone back
  on after a power-off, as for Android's power-off charging; LK then boots
  `boot_a` (iOS) instead of a charger UI. This is expected platform
  behaviour, not a kernel fault.
- Shutdown finished well before the 60 s halt timer in both runs (E37b and
  E38 stalled until a timer). Not explained yet; no log exists for a cold
  power-off. Possibly CPU_OFF in `quiesceCPU` now running for real.

- A user restart does not keep RAM contents (E39c), whereas E38's panic
  reset did, so the LASTLOG page cannot show logs from before a user
  restart. Why the two resets differ is not established.
