# E42–E47: USB serial console (kernel patch 0210)

**Result: PASS (E47 full speed, E48 high speed).** With `g54usb=1` the G54 enumerates on a
Windows 11 host as a CDC-ACM serial port ("USB Serial Device (COM8)", USB ID
`1209:0003`, serial `G54XNU0001`, Windows' inbox `usbser`). Opening the port
replays the whole SWEET log ring and then follows it live:
`scripts/g54_console.ps1` captured 211,332 bytes / 2,990 clean lines in 45 s,
from `Darwin Kernel Version 22.6.0 … xnu-8796.141.3` to live iOS output.

## Hardware facts used (stock 5-8-6 package)

| Item | Value | Source |
| --- | --- | --- |
| Controller | MediaTek MUSB (`mediatek,mt6855-usb20`, `musb-hdrc`) at `0x11210000`, SPI `0x180`; **not** ruby's MTU3 | vendor_boot DTB |
| Clocks | `pericfg_ao` `0x11036000` set/clr gates: `usb_phy`/`usb_sys` bank 0 bits 30/31 (sta `0x10`, clr `0x2c`), `usb_dma_bus`/`usb_mcu_bus` bank 1 bits 0/1 (sta `0x14`, clr `0x34`); already ungated at handoff (`sta 00000000`) | `clk-mt6855-peri.ko` gate table |
| PHY | T-PHY v2 `0x11e40000`, U2 bank `+0x300`; eye vrt 5, term 5, discth 9, rx_sqth 5; device mode `U2PHYDTM1 \|= 0x202` | DTB, `phy-mtk-tphy.ko` `u2_phy_instance_set_mode` |
| PHY rail | `VUSB` (MT6369) `regulator-always-on` | DTB |
| Interrupt status | `INTRUSB`/`INTRTX`/`INTRRX` are **write-1-to-clear** (not clear-on-read as in the Mentor core) | `musb_hdrc.ko` `mt_usb_interrupt` reads then writes them back |
| MUSB `HWVERS` | `0xe503` | E47 log |

## Runs

| Run | Kernel / change | Observation | Finding |
| --- | --- | --- | --- |
| **E42** | K13a (CI 43586587606), `g54usb=1`, high speed | Windows: "Device Descriptor Request Failed". LASTLOG: `power 70` (HS), `devctl 99`, `setups 8` | Clocks, PHY, MUSB and soft-connect work; EP0 fails |
| **E43** | K14 (+ per-SETUP log, `g54usbfs`, `g54usbsrc`), full speed | Same failure; `setup 00 05` (SET_ADDRESS) seen | Not a HS signal problem |
| **E44** | K15: write FADDR on the EP0 interrupt flag | Address written at spin 0; `csr0 0008` stuck | Flag still set from the SETUP (later understood: W1C) |
| **E45** | K16: write FADDR when CSR0 DataEnd clears | `faddr 01`, `csr0 0000`; `setups 4`, then failure | SET_ADDRESS fixed |
| **E46** | K17 (+ request history, `g54usbfifo=1` byte FIFO writes) | `hist 0601/40:R18 0500/00:a0 0601/12:R18 0602/FF:R75`; resets in the thousands | Device descriptor fine; every request cut by a phantom "bus reset": `INTRUSB` RESET latched |
| **E47** | K18 (CI 43603524773, patchset `ca05fefa…`): status registers written back (W1C) | **Enumerates; COM8; full log over USB** | PASS |
| **E48** | K18, `g54usb=1` without `g54usbfs` | **Enumerates at high speed** (`power 70`, `configured (high speed)`, one bus reset), COM8, replay from byte 0; no slew-rate tuning needed | PASS |

E47 enumeration (driver log): GET_DESCRIPTOR device(64) → reset → SET_ADDRESS 1
(address applied after 1 spin) → device(18) → configuration(255, 75 bytes) →
string `0xEE` (stalled, no MS OS descriptor) → strings → device qualifier →
configuration(9, 75) → SET_CONFIGURATION 1 (`configured (full speed)`) → CDC
GET/SET_LINE_CODING, SET_CONTROL_LINE_STATE 3 →
`port open, replaying log from 0 of 105473`.

## Process notes

- The probe's filtered page (`-D LASTLOG_GREP="G54 USB"`, substring match)
  made E43–E46 readable; console lines from several CPUs interleave, so the
  match must not require a line start.
- K18 moved `sweet_log_ring`/`sweet_log_total` to `0x…7c7a5f8`/`0x…7c7a5f0`:
  LASTLOG flags for K18 are `-D LASTLOG_RING=0x141c7a5f8 -D LASTLOG_TOTAL=0x141c7a5f0`.
- Windows: no driver install; the console script uses .NET `SerialPort`.
- Not tested yet: macOS host, very long sessions, bulk throughput (E48's
  capture was limited by the log rate), the ZLP path on bulk IN.
